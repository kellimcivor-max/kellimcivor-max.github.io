Context layer in plain English

Why Glean’s context is richer than a simple retrieval layer

A context layer is only useful if it helps the model understand not just where data lives, but what it means, who it belongs to, what relationships matter, which tools should be used, and which policies apply. That is the distinction between connectivity and enterprise understanding.

01 Understand query

Intent

Interpret the real work objective, not just keywords.

02 Make a plan

Search strategy

Determine what sources, tools, and steps are actually needed.

03 Retrieve data

Best-fit index

Pull the right content from purpose-built indexes and live systems.

04 Understand data

Graph context

Disambiguate entities, relationships, ownership, and authority.

05 Use tools

Action path

Select approved actions and agents instead of forcing the model to guess.

06 Evaluate

Governed loop

Check quality, policy, and next best action before completion.

Why this is richer than federated-only AI
  • Purpose-built indexes improve retrieval quality instead of forcing every answer through live source queries.
  • Graph context helps resolve people, content, ownership, systems, and relationships across the estate.
  • Permissions, auditability, and policy can be governed once and reused across Byron, Copilot, and future agents.
What Northern Trust gains
  • A shared context layer beneath Byron instead of duplicating retrieval logic by agent or team.
  • More grounded answers from Microsoft, ServiceNow, and other enterprise sources.
  • A cleaner operating model for independent agents, connector sprawl, and model choice over time.

Control points built into the calendar

The structure of the pilot deliberately sequences technical activation before broader user exposure.

Security and access

  • Identity and SSO are addressed before scale.
  • Permissions are validated before wider user rollout.
  • Governance review happens before launch decisions.

Connector readiness

  • Microsoft and workflow systems are activated early.
  • Crawls and freshness are checked before user evaluation.
  • Source issues can be remediated before scale decisions.

Business proof

  • Champions and surveys create a feedback loop.
  • Weekly scoring shows whether the use cases are landing.
  • The final readout ties launch to measured outcomes.
